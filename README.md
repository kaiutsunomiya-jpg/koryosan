# 校了さん v11 — 会計・検索 追加

## 追加機能
- **会計**（新画面）: 収入 / 支出・日付・担当者・品目・金額・備考。入力600ms後に差分保存、選択欄は即時保存。収入=薄青、支出=薄赤。全て/収入/支出の表示切替。合計収入 / 合計支出 / 収支合計は全件から算出します（フィルタの影響を受けません）。表の下の＋で行追加。削除は確認あり。
- **検索**（新画面）: タスク、曲名・歌詞・追記メモ、スケジュール、タイテ、セトリ、会議、会計、空き日程の文字列を対象に完全な文字列の連続一致（リテラル部分一致、大文字小文字を区別、あいまい検索なし）。最大10件。タップで画面を開き、可能なら該当行へ移動。検索語はFirebaseには送信しません。
- 画面順: タスク、曲リスト、スケジュール、メトロノーム、練習タイテ、セトリ作成、会議、会計、空き日程、検索。スマホは下部メニューを横スクロール。

## Firebase設定（必須）
Realtime Database → Rules の `rules.bands.koryosan` 内に、既存の `tasks` 等と同じ階層で追加：

```json
"accounting": {
  "$entryId": {
    ".write": "auth != null && root.child('members').child(auth.uid).val() === true"
  }
}
```

既存の `bands.koryosan` に `.read` があり、ログイン済み・membersに許可されていれば読み込めます。上記は追記用の断片です。ルール全文を置き換えないでください。ルールの構成によっては `.validate` を追加して項目の型や金額の上限を制限することも検討してください。

データ構造は `/bands/koryosan/accounting/{記録ID}` 以下に次の形式で自動生成されます：

```json
{
  "type": "income",
  "date": "2026-11-21",
  "member": "🐧",
  "item": "ライブ物販",
  "amount": "2500",
  "notes": "",
  "createdAt": 1795200000000,
  "id": "記録ID"
}
```

※ 金額は数字のみの文字列として保存します（計算時に数値化）。未入力なら空文字です。会計データをまだ登録していない場合、`accounting` ノードは存在しなくても正常です。**既存のDB JSONをインポートし直す必要はありません。** 既存の曲・歌詞・タスク・スロットは保持されます。

## 公開手順
1. Firebase Realtime DatabaseのJSONをバックアップ。
2. Firebase Rulesに `accounting` の書き込み許可を追加し Publish。
3. このフォルダのPWA一式をGitHub Pagesの `koryosan` リポジトリにアップロードし、公開後に左下の `v11` を確認。
4. 2端末で会計を1件追加して同期を確認。検索でその品目を検索して会計に遷移できることを確認。

## 注意
- 会計入力の通信は差分更新。検索はFirebaseへの追加通信を行いません。
- 検索は最大10件で、同じフレーズを含む候補は画面の種類順に選出されます。
- 1つのフィールドの同時編集は競合する可能性があります。
- アプリを以前のバージョンに戻した場合、会計画面と会計入力は表示されませんが、Firebaseの既存 `accounting` データは削除されません。
